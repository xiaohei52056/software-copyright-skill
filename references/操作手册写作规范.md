# 操作手册写作规范

读者是版权中心审核员和最终用户，不是开发者。目标：让审核员看完能相信"这个软件真实存在、功能与申请表描述一致、截图与文字对应"。

## 核心原则：截图是唯一事实来源（用户硬性要求）

**业务逻辑 100% 由截图决定，不可无中生有。**

- 截图里有什么页面，手册就必须有对应二级小节和文字描述；**截图中没有的功能一律不写**。
- 代码、业务理解、路由清单只用于**解读截图中出现的内容**（帮助看懂页面在干什么），不作为新增功能的依据；即使代码里功能再多，截图没有就不写。
- 每张截图**不可缺少**：每张截图必须被正文引用，每个功能二级小节必须有图。
- 截图清单（`scan_screenshots.py` 生成）是章节结构的唯一来源：截图有什么页面，手册就有什么章节。

## 精简与去重（用户硬性要求）

**只写页面的主要功能，内容不啰嗦、不堆砌。**

- 每个功能二级小节：**1 段主要功能描述（含关键字段）+ "如图所示，" + 截图 + 1~3 条主要操作**即可；不逐条罗列所有按钮，不写"便于/方便/帮助用户"式的冗余收尾句。
- **重复文本控制**：相同句式（如"点击××按钮，即可完成××操作"）出现频率不能太高；相邻小节不要用同一套话术。写作时通读全文，删掉重复表达。
- 每句以句号/分号分层，独立成段；**正文顶格**（无首行缩进、行首不留空格），`build_manual_docx.py` 默认顶格（旧样式缩进可加 `--indent`）。

## 固定句式（对齐已过审成品风格）

每个功能小节按以下骨架写，全部用连贯段落，**不使用表格**（成品为全段落风格）：

```
在 XX 系统中，{页面名}页面所展示的信息有序号、{字段1}、{字段2}、……、操作等字段信息。
如图所示，
[截图]
点击上方的搜索框，输入 {关键词}，点击搜索按钮，即可进行查询操作。
点击上方{颜色}的{新增|添加}按钮，输入 {字段} 等相关的字段信息，点击提交，即可完成添加操作。
点击操作字段中的{编辑|删除|重置密码|分配权限|导出}按钮，即可完成 {操作}。
```

- 页面名、字段名、按钮名**必须与截图/页面完全一致**（来自 `extract_fields.py` 提取或截图本身）。
- 按钮带颜色时写出来："点击上方**绿色**的新增按钮"、"点击上方**蓝色**的添加按钮"（以截图实际颜色为准）。
- 每段功能小节以"在 XX 系统中，……"开头（与申报全称一致），以"如图所示，"引出截图。

## 结构

```
封面：软件全称 / V1.0 / 用户手册          ← 脚本自动生成
目录                                       ← 脚本自动生成（Word 域或静态）
一、首页 / 二、系统管理 / 三、……          ← Heading 1 = 截图页面分组（菜单顺序）
  1. 用户管理 / 2. 角色管理 / ……          ← Heading 2 = 截图页面（一个页面一个小节）
```

- 一级章节按 `extract_menu.py` 提取的左侧菜单顺序，二级小节 = 截图页面名，与系统界面文字**一字不差**。
- 标题编号默认 `--heading-style cn`（一级"一、首页"，二级"1. 用户管理"，对齐成品）；可选阿拉伯（1 / 1.1）。
- **软件概述 / 系统登录 / 常见问题 默认关闭**（R011）：只写截图对应的功能章节；用户明确要求时才加，且这些章节不需要截图（自检豁免）。

## 内容素材：真实字段名（R005）

写页面描述前先看 `页面字段清单.md`（`extract_fields.py` 生成，从 .vue 提取）：

- 列表页：**"页面所展示的信息有序号、{列名}、{列名}、操作等字段信息。"**（用真实列名）
- 操作步骤：**"点击{按钮名}按钮，即可完成……"**（用真实按钮文字）
- 表单页：描述表单字段与校验规则（真实 label）。
- 字段名以截图中实际显示的为准；`extract_fields.py` 提取结果只作参考，两者冲突时**以截图为准**。

## 篇幅硬指标

- 除目录外 ≥20 页（实操建议）；**用户明确选择精简文案时，页数不足 20 页自检降为警告**，接受可能补正的风险。
- 每页文字 ≥30 行（有图页除外）；**每页不能全是图** → 每张截图前后都要有文字。
- 经验值：15–25 张截图 + 8000–12000 字正文 ≈ 25–30 页；精简模式（每节只写主要功能）约 12–18 页。
- 一个二级小节 1–3 张截图，每张必须有说明文字。

## 截图规则（实操必须）

1. 完整窗口：含浏览器标题栏/标签栏、系统顶栏、菜单栏、关闭按钮，能看出功能跳转。
2. 标题栏里的系统名称与申报全称不符时（R013）：给出警告让用户选择 A 继续 / B 重新截图，**不阻断流程**；交付时再次提醒补正风险。
3. 只允许对客户 logo 打码，其余任何位置不打码；打码面积大会补正。
4. 清晰、无水印、无遮挡；分辨率 ≥300dpi 或原始屏幕分辨率。
5. 截图文件放 `草稿/截图/`，命名 `NN-页面名.png`，Markdown 里用 `![图 N-x 页面名](截图/NN-页面名.png)` 引用；文件名前缀编号便于 `scan_screenshots.py` 生成清单。

## 措辞

- 写页面、按钮、字段、结果；不写框架名（Vue/Spring）、接口、状态管理、数据库表、异步任务。
- 禁止贴任何代码片段（说明书禁止"功能函数代码"）。
- 禁用空话：赋能、一站式、智能化、高效便捷、旨在、全方位、打造、深度融合。
- 正文用连贯段落，操作步骤用"1. 2. 3."编号句，少用项目符号堆砌。
- 模块名、按钮名与系统界面上的文字一字不差；一级标题与申请表"主要功能"中提到的模块名一致。

## 没截图时

- **截图中没有的功能页面，一律不写**（用户硬性要求：不可无中生有）。
- 需要截图但尚未提供的页面：保留醒目占位 `【截图预留：请插入「××页面」截图。】`，脚本渲染成红色加粗；`check_consistency.py` 会拦截未替换的占位。
