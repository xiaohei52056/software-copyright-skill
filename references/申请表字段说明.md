# 申请表字段说明（对照 templates/申请表模板.docx）

字段顺序与模版表格一致。"填写要点"来自版权中心登记系统要求与实操经验；"示例值"取自 `examples/设备点检系统/申请表信息.yaml`（**虚构示例**，仅示范格式）。

## 模板优先规则（硬性）

- **用户提供了申请表模板时**：`fill_application_form.py --template <客户模板>` 严格照客户模板填——只填模板中已存在的字段，不新增行/列，**不可无中生有**；模板未包含的字段不写入，脚本会列出"模板未找到的字段"供手工补填。
- **用户没有申请表模板时**：使用默认模板（skill 自带 `templates/申请表模板.docx`）。
- 检测到模板（`detect_existing.py` 会识别 `*申请表*模板*.docx` 等）时，先向用户确认用哪一份。

## 主要功能详版写法（500–1300 字）

按这个骨架写一段连贯正文（不用小标题、不用项目符号）：

1. **研发背景**（1–2 句）：面向什么行业、解决什么具体问题。
2. **系统架构**（1–2 句）：前后端/数据库怎么分层，一句话说清，不堆框架名。
3. **各功能模块**（主体）：按手册章节顺序逐个说"模块名 + 做什么 + 输入什么输出什么"，模块名与手册一级标题一字不差。
4. **技术实现方式**（2–3 句）：关键算法/数据模型/流程引擎等，用业务语言。
5. **业务应用场景**（1–2 句）：谁在什么场景下用，达到什么效果。

> R002（改版）：**只保留详版 500–1300 字**，简版官网填报不再生成，避免两版内容不一致。yaml 中不要写"软件的主要功能（简版）"字段。
